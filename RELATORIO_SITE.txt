1. VISÃO GERAL DO PROJETO
════════════════════════════════════════════════════════════════════════════════

Nome do projeto  : Site Studio Tatto
Tipo             : Site comercial de estúdio de tatuagem + loja de joalheria
Estrutura        : Monorepo (pnpm workspaces)
Diretório raiz   : c:\Users\User\Documents\GitHub\Site_Tatto

STACK TECNOLÓGICO
─────────────────
  Frontend   : React 18 + TypeScript + Vite 5 + Tailwind CSS v4
  Animações  : Framer Motion 12 + Three.js (anel 3D interativo)
  UI Library : shadcn/ui (38 componentes Radix UI)
  Backend    : Node.js + Express 4 (ESM)
  Base dados : PostgreSQL (pool de 10 conexões)
  Email      : Nodemailer via SMTP Gmail
  Uploads    : Multer + ffmpeg-static (transcodificação de vídeo)
  Pagamentos : InfinitePay (integração via OAuth2)
  Auth       : JWT (clientes via httpOnly cookie | admins via sessionStorage)

6. AUDITORIA DE SEGURANÇA — ESTADO FINAL (15/06/2026)
════════════════════════════════════════════════════════════════════════════════

CORREÇÕES APLICADAS NESTA SESSÃO
──────────────────────────────────

  [BACKEND — siteRepository.mjs]
  ✅ SQL Injection no filtro 'category' das joias
     Antes : concatenação de string ` AND category = '${category}'`
     Depois: query parametrizada com $2

  [BACKEND — index.mjs]
  ✅ Endpoint /api/admin-media/ingest sem autenticação
     Adicionado middleware requireAdmin

  ✅ Limite de upload 1GB → 50MB
     Reduzido de 1GB para 50MB (proteção contra DoS)

  ✅ JWT_SECRET e ADMIN_JWT_SECRET com valores padrão fracos
     Servidor recusa iniciar se variáveis não definidas no .env

  ✅ JWT de cliente válido 30 dias → 7 dias

  ✅ Sem headers de segurança
     Adicionado helmet() — X-Frame-Options, X-Content-Type-Options, etc.

  ✅ Sem rate limiting nos endpoints de autenticação
     Adicionado: 10 tentativas por 15 minutos por IP

  ✅ Sem rate limiting nos formulários públicos
     Adicionado: 20 envios por hora por IP
     Afeta: /api/reviews, /api/contact-submissions, /api/course-enrollments

  ✅ Senha de clientes: mínimo 6 caracteres → mínimo 8 + maiúscula + número

  ✅ Preços calculados apenas no browser (vulnerável a manipulação)
     Servidor agora vai buscar preços reais à base de dados ao criar encomenda

  ✅ Senhas de admin hardcoded no código (fallback)
     Removido o fallback — servidor recusa login sem variável definida no .env

  ✅ Email sem validação de formato
     Adicionada validação regex em /api/contact-submissions e /api/course-enrollments

  ✅ Token JWT de cliente no localStorage (vulnerável a XSS)
     Migrado para cookie httpOnly — não acessível por JavaScript
     Novo endpoint POST /api/auth/logout para limpar a sessão
     Frontend atualizado: credentials:'include' em todos os pedidos de auth

  [FRONTEND — html.ts]
  ✅ XSS via dangerouslySetInnerHTML (sanitização incompleta)
     Substituído normalizeHtml caseiro por DOMPurify com lista branca de tags

  [FRONTEND — Specialists.tsx]
  ✅ Keys em listas usando name+index
     Corrigido para usar specialist.id como chave principal

10. PARA COLOCAR EM PRODUÇÃO
════════════════════════════════════════════════════════════════════════════════

  1. Definir NODE_ENV=production no servidor de produção
  2. Atualizar CORS_ORIGINS com o domínio real (ex: https://seusite.com)
  3. Usar HTTPS (os cookies httpOnly ficam 'secure' automaticamente em produção)
  4. Executar o build do frontend:
       npm run build   ou   npx vite build --config frontend/vite.config.ts
  5. Iniciar o servidor:
       node backend/server/index.mjs
  6. O servidor serve o frontend compilado a partir de frontend/dist/
  7. Certificar que todas as variáveis de ambiente estão definidas
     (o servidor recusa iniciar sem JWT_SECRET e ADMIN_JWT_SECRET)
